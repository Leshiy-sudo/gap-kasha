## Часть 2. Убрать Google-авторизацию и регистрацию, добавить вход по номеру телефона с OTP-кодом только через Telegram

### 2.1. Способ доставки — Telegram Gateway API (выбрано, не свой бот)

Обычный Telegram-бот **не может первым написать пользователю по номеру телефона** — только тому, кто сам нажал Start. Чтобы пользователь вводил **только номер телефона** и не совершал никаких действий в Telegram, используется официальный сервис Telegram — **Gateway API** (`core.telegram.org/gateway`), а не собственный бот. Это отдельный платный продукт самого Telegram: он доставляет код напрямую в аккаунт пользователя тем же механизмом, каким Telegram доставляет свои родные коды входа, — диалог/бот/подписка пользователю не нужны вообще.

Ключевые детали сервиса:
- Аутентификация backend → Gateway: HTTP-заголовок `Authorization: Bearer <token>`, токен выдаётся в личном кабинете на gateway.telegram.org.
- `checkSendAbility(phone)` — бесплатно проверяет, привязан ли номер к Telegram, до реальной отправки. Если сразу вызвать `sendVerificationMessage` следующим шагом — второй вызов тоже бесплатный (тариф считает только «отправки без предварительной проверки»).
- `sendVerificationMessage(phone_number, code, ttl, ...)` — отправляет код; код можно сгенерировать самим (передать в `code`) и переиспользовать существующую логику хранения/сравнения хешей, ИЛИ дать Telegram сгенерировать его (`code_length`) и потом свериться через `checkVerificationStatus`. **Рекомендация: генерировать код на своём бэкенде** (как сейчас с email-OTP) и просто передавать его в `sendVerificationMessage` — так весь код проверки, хеширования, TTL, лимитов попыток остаётся 1:1 как есть, меняется только «канал доставки».
- Стоимость: $0.01 за каждую доставленную попытку; отправка на свой собственный телефон (для разработки/тестов) — бесплатно.
- Если у номера нет Telegram-аккаунта — `checkSendAbility` заранее вернёт это, входа через этот способ у такого номера не будет (SMS-фолбэка нет по твоему требованию — приложение должно явно показать «этот номер не найден в Telegram»).

Никакого своего бота, вебхука, `telegram_chat_id`, диплинков и разницы «первый/повторный вход» **не нужно** — это всё было актуально только для схемы с собственным ботом и теперь снято. Флоу для пользователя одинаковый каждый раз: ввёл номер → получил код в Telegram (просто как сообщение, автоматически) → ввёл код → готово.

### 2.2. Backend (`local-backend/`)

Токен доступа — новая переменная окружения `TELEGRAM_GATEWAY_TOKEN` (по аналогии с уже существующими `JWT_SECRET`, `OTP_PEPPER` в `.env`).
